Online Shoppers Purchasing Intention Dataset (UCI ML Repository)	Dataset público de sesiones de un sitio de e-commerce, con variables de navegación (páginas administrativas, informativas y de producto visitadas, duración por tipo de página, bounce rate, exit rate, valor de página, proximidad a fecha especial, tipo de visitante, mes, etc.) y una variable objetivo binaria "Revenue" que indica si hubo compra. El dataset consiste en vectores de características de 12,330 sesiones, formado de modo que cada sesión pertenece a un usuario distinto dentro de un período de un año.	Es la base de datos académica más citada para modelar intención de compra a partir de comportamiento de navegación; usa exactamente el tipo de variables (clics, tiempo de navegación, páginas de producto) que planeamos emplear.	El conjunto de datos tiene 10 atributos numéricos y 8 categóricos, publicado por Sakar y Kastro en 2018 en el UCI ML Repository (DOI 10.24432/C5F88Q). Los autores originales aplicaron perceptrón multicapa (MLP) y redes LSTM para predecir la intención de compra.	Dataset gratuito, limpio, documentado y ampliamente reutilizado en literatura académica; permite comparar resultados propios contra estudios previos.	La etiqueta es binaria (compra/no compra), no una clasificación en 3 niveles como exige nuestro MVP; solo el 15.5% de las 12,330 sesiones terminó en compra, lo que genera un desbalance de clases relevante para el modelado; datos de un único sitio y año (2018), sin variable explícita de "producto agregado al carrito".	Qué variables de sesión son informativas y cómo estructurarlas (duración por tipo de página, bounce/exit rate); puede servir como dataset de respaldo o de validación si no conseguimos datos propios de una tienda real.	https://archive.ics.uci.edu/dataset/468/online+shoppers+purchasing+intention+dataset (Sakar, C. & Kastro, Y., 2018, DOI 10.24432/C5F88Q)
Google Analytics 4 — Métricas y audiencias predictivas (Purchase probability)	Los modelos de machine learning de GA4 asignan a cada usuario una probabilidad de compra en los próximos 7 días, una probabilidad de abandono (churn) y un ingreso predicho a 28 días, y permiten construir audiencias basadas en esos umbrales. Estas métricas se calculan automáticamente enriqueciendo los datos de eventos estructurados que la plataforma ya recolecta.	Enfoque comercial equivalente a nuestro objetivo (estimar intención de compra a partir del comportamiento), aunque orientado a activación de marketing y no a clasificación explícita en niveles.	Modelo de ML propietario de Google entrenado sobre eventos estándar de GA4 (purchase, in_app_purchase, etc.); para ser elegible se requiere un mínimo de 1,000 usuarios con resultado positivo y 1,000 con resultado negativo (compras o abandono) en una ventana de 7 días.	Integración nativa en tiempo real; no requiere que el usuario entrene ni mantenga el modelo; ya validado sobre grandes volúmenes de tráfico.	Es una caja negra: no se conocen las variables exactas ni el algoritmo; si el evento de compra no usa el nombre estándar de GA4, el modelo de probabilidad de compra simplemente no se entrena; la salida es un percentil/probabilidad continua, no una etiqueta baja/media/alta; requiere alto volumen de datos, inviable para un proyecto académico con datos limitados.	La definición de ventanas temporales (ej. "activo en últimos 28 días, predicción a 7 días") y el uso de percentiles para segmentar usuarios; útil como referencia para decidir cómo discretizar una probabilidad continua en 3 niveles.	https://support.google.com/analytics/answer/9846734 ; https://support.google.com/analytics/answer/9805833
Adobe Customer AI (Adobe Experience Platform Intelligent Services)	Asigna un puntaje de propensión personalizado a cada individuo en la base de datos de clientes, prediciendo qué tan probable es que esa persona realice una acción específica —como abandonar, comprar o hacer clic— dentro de una ventana de tiempo definida, usado luego para segmentar campañas. El sistema identifica los principales factores que influyen en cada predicción individual.	Comparte el objetivo de estimar propensión/intención a partir de comportamiento, con un componente de explicabilidad (mostrar "por qué") que es relevante para nuestra interfaz de resultados.	Usa machine learning sobre datos de eventos de experiencia del cliente, generando puntajes a nivel de perfil individual (no agregado), integrados con Real-Time CDP, Journey Optimizer y Adobe Target.	Explicabilidad a nivel de usuario individual (factores principales de cada predicción); granularidad fina, no solo segmentos agregados.	Solución empresarial cerrada, requiere infraestructura de Adobe Experience Platform; Adobe aclara explícitamente que Customer AI no está diseñado para pricing dinámico ni recomendaciones de producto, es decir, su alcance funcional es distinto al de un análisis de comportamiento e-commerce de propósito general; detalles exactos del algoritmo no publicados (No verificado).	El valor de mostrar al usuario final "qué variables explican" el nivel de intención asignado, y de separar claramente la capa de predicción de la capa de uso/activación de resultados.	https://experienceleague.adobe.com/en/docs/experience-platform/intelligent-services/customer-ai/overview
1. Principales diferencias con nuestro proyecto
Tipo de salida: el dataset UCI produce una etiqueta binaria (compra/no compra) y GA4/Adobe producen probabilidades continuas o percentiles; nuestro MVP exige una clasificación explícita en tres niveles (baja/media/alta), lo cual implica una etapa propia de discretización que ninguna de las tres soluciones resuelve directamente.
Naturaleza y transparencia del modelo: GA4 y Adobe Customer AI son sistemas propietarios de caja negra sobre infraestructura comercial; nuestro proyecto, al ser académico, puede (y debe) documentar completamente variables, algoritmo y umbrales usados.
Propósito final: GA4 y Adobe están orientados a activar campañas de marketing o personalización en tiempo real; nuestro MVP está orientado a análisis y visualización (tablas y gráficos) para fines de estudio, no a ejecutar acciones automáticas sobre el usuario.
2. Tres oportunidades de diferenciación técnica para el MVP
Clasificación multinivel explícita y documentada (baja/media/alta), en lugar de solo una probabilidad continua (GA4) o una etiqueta binaria (dataset UCI), con criterios de umbral justificados y reproducibles.
Interpretabilidad abierta dentro del propio dashboard: mostrar qué variables de navegación influyeron más en la clasificación de cada usuario, en la línea de lo que hace Adobe Customer AI, pero de forma transparente y accesible (no caja negra).
Funcionamiento con volúmenes de datos moderados: mientras GA4 exige miles de eventos positivos/negativos para activar sus modelos predictivos, nuestro modelo puede entrenarse y mostrarse útil con datasets académicos de tamaño medio (como el de UCI), lo cual es relevante para un contexto de 12 semanas sin acceso a tráfico masivo real.
3. Tres riesgos a considerar en la comparación
Expectativas de desempeño poco realistas: comparar métricas de un modelo académico entrenado con datos abiertos limitados contra sistemas de producción entrenados con datos masivos (GA4, Adobe) puede llevar a conclusiones injustas sobre la calidad relativa del MVP.
Dependencia de datos de terceros: si se usa el dataset UCI en lugar de datos propios de una tienda real, los resultados reflejan el comportamiento de un sitio específico de 2018, con posible desbalance de clases, y no necesariamente generalizan a otro contexto de e-commerce.
Ausencia de un estándar validado para 3 niveles: a diferencia de GA4 (que usa percentiles calibrados sobre miles de usuarios) o Adobe (con validación empresarial), nuestro esquema baja/media/alta requerirá definir y justificar sus propios umbrales, sin un benchmark externo directo para validarlos estadísticamente.
